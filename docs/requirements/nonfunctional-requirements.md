# Non-Functional Requirements

## 1. Overview

本書は Safar の非機能要件を定義する。運転中・荷役中・圏外という利用文脈に起因する、オフライン・安全性・プライバシーを最重要とする。出典は `Safar_要件定義書.md` 6章および機能概要書 4.5。

---

## 2. Non-Functional Requirements

| NFR ID | Category | Title | Requirement | Priority |
|---|---|---|---|---|
| NFR-001 | オフライン | 圏外での中核参照 | 現場フレーズ・商品DB・ハラル店リストは圏外で参照でき、オンライン復帰時に同期する。 | Must |
| NFR-002 | 安全性 | 運転中の安全操作 | 運転中は画面注視を要する UI を避け、音声・通知主体とし、ハンドル操作を妨げない。 | Must |
| NFR-003 | プライバシー | 要配慮情報の保護 | 位置情報を最小収集・明示同意・保存時暗号化し、同意撤回手段を備える。 | Must |
| NFR-004 | 信頼性 | 判定は安全側に倒す | ハラル判定は確証がない場合「疑わしい」に倒す（誤OKのリスクを誤avoidより重く扱う）。 | Must |
| NFR-005 | 多言語 | 露/日対応と拡張性 | UI・コンテンツを露/日で提供し（MVP）、ウズベク語拡張を阻害しない構造とする。 | Must |
| NFR-006 | 性能 | 走行中の実用応答 | スキャン判定・先回り通知は走行中に実用的な応答時間で動作する（目標値は別途定義）。 | Must |
| NFR-007 | 可用性 | 障害時の影響限定 | 外部プロバイダ（OCR/翻訳/地図）の障害時も、オフライン中核機能の利用を維持する。 | Should |
| NFR-008 | 監査性 | エラーログ | 障害調査のためのエラーログを記録・確認できる。 | Should |
| NFR-009 | 保守性 | データ更新運用 | 商品DB・スポットDB・フレーズ辞書を運用更新できる構造とする。 | Should |
| NFR-010 | 互換性 | 対応端末 | 一般的な iOS / Android 端末で動作する（対応バージョンは別途定義）。 | Must |
| NFR-011 | アクセシビリティ | 運転文脈の操作性 | 運転・荷役中でも理解できる UI・音声フィードバックを提供する。 | Should |

---

## 3. Notes

- `NFR ID` は `NFR-001` 形式で採番する。
- 性能・対応 OS・アクセシビリティ基準の **定量目標は実装着手前に別途確定** する（[architecture.md](../architecture/architecture.md) Open Questions、各 OpenSpec change 参照）。
- 実装・インフラ詳細は `architecture/` と `specifications/` で管理する。
