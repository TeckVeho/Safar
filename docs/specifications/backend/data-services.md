## 2. 荷物チェック（FR-026〜029）

### 2.1 入力
- 伝票/送り状の撮影画像（OCR）/ JAN コード

### 2.2 処理順
1. 伝票 OCR で品目リスト（商品名/JAN）を抽出
2. 各品目を商品DB で照合し、豚由来成分を検出
3. 未登録商品は商品名から NG 成分辞書でテキスト照合（フォールバック）
4. 豚含有品があればアラート＋対応オプションを返す

### 2.3 判定

| 区分 | 条件 |
|---|---|
| 豚含有あり | 品目に豚由来成分を検出 |
| 豚含有なし | 品目に豚由来成分が検出されない |
| 確認必要 | 由来不明・情報不足の品目がある |

### 2.4 共用基盤
- 商品DB（`product`）・NG 成分辞書（`ng_ingredient`）はハラル判定（§3）と共用
- 伝票 OCR 基盤はフレーズ/翻訳（§5）の伝票カメラ翻訳と共有

> Open: 伝票フォーマットの多様性への対応方針、荷主との連携フロー。

## 3. ハラル判定（FR-006〜009）— 中核

### 3.1 入力
- JAN コード（優先） / 成分ラベル OCR テキスト（フォールバック）

### 3.2 処理順
1. JAN 照合で商品・成分を取得
2. 未登録/読取不可 → OCR 成分テキストを解析
3. **NG 成分辞書**（豚由来・アルコール〔みりん・料理酒等〕・動物性ゼラチン）に照合
4. 区分判定し、**根拠**（該当成分名・該当箇所）を付与

### 3.3 判定区分

| 区分 | 条件 |
|---|---|
| `ok`（食べてOK） | NG 成分が検出されない |
| `avoid`（避けて） | NG 成分を検出 |
| `maybe`（疑わしい） | 由来不明（例: ゼラチンの由来表記なし）・情報不足・確証なし |

### 3.4 安全側フォールバック（FR-009 / NFR-004）
- 確証が持てない場合は必ず `maybe`。`ok` を安易に返さない
- 出力に「最終判断はユーザー」を明示するフラグ/文言を含める

### 3.5 共用基盤
- 商品DB（`product`）・NG 成分辞書（`ng_ingredient`）は荷物チェック（§2）と共用

> Open: 商品DB 調達・更新、OCR エンジン、NG 成分辞書のメンテ主体（[architecture.md](../../architecture/architecture.md) A3/A4）。

## 6. エラー/オフライン方針

- 判定不能・読取失敗は誤った `ok` を返さず `maybe`／明示エラー
- 外部プロバイダ障害時はオフライン中核機能を維持（NFR-007）
- エラーはログに記録（NFR-008）
